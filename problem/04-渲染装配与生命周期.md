# 渲染装配与生命周期

---

## 4.1 主进程入口写了顶层 `await`，直接死锁

**症状**：Electron 起来没窗口，也不报错，进程活着。
**根因**：Node ESM 的顶层 await 与 Electron 的 `app.whenReady()` 装配顺序冲突。
**修法**：入口不用顶层 await，一律 `void app.whenReady().then(...)`；
`app.quit()` 在 ready 之前调用不保证拦住回调，所以 then 里还要再挡一次锁标志。
**怎么验**：`npm run build` 后直接 `npm start`；入口形状写在 `src/main/index.ts` 顶部。
**教训**：Electron + ESM 的两条硬规矩：相对 import 必须带 `.js`；入口不许顶层 await。

---

## 4.2 preload 不能 import 任何东西

**症状**：把通道名从 `shared/ipc.ts` import 进 preload，沙箱里直接炸。
**根因**：`contextBridge` + preload 沙箱限制。
**修法**：`src/preload/index.cjs` 单文件、零 import、消息名字符串就地内联。
**怎么验**：`test/preload-contract.test.ts` 读那段内联字符串，与 `shared/ipc.ts` 逐个比对——
两边跑偏会立刻红。
**教训**：不得不复制的字符串，必须有一条测试把它钉在源头。

---

## 4.3 常驻 PowerShell 子进程的三件事

**症状**：全屏让路探测要在退出时干净收掉，脚本还先炸过一次。
**根因**：三个独立小坑叠在一起——
① `.ps1` 里写中文：WinPS 5.1 按 ANSI 读 UTF-8，解析直接失败；
② 子进程不知道父进程何时死掉，会变成孤儿；
③ 它可能在宠物正隐藏时死掉（见 [01-窗口与鼠标穿透.md](01-窗口与鼠标穿透.md) 1.11）。
**修法**：脚本内容**纯 ASCII**（要中文就 base64 走 `-EncodedCommand`）；
每轮检查 `Get-Process -Id $parent` 判父进程存活；`close` 事件里恢复显示；
`process.once('exit')` 里 kill。
**怎么验**：e2e 两条——「让路探测子进程已启动」「退出后没有残留的探测子进程」。
**教训**：拉子进程就欠三条债：怎么起、怎么确认它该活着、怎么确认它死了。中文这条坑我后来
在探针脚本上又踩了两次（见 06）。

## 4.4 退出时清理的顺序与残留

**症状**：审查指出 `startCursorPolling` 返回的停止函数被丢掉、租约 sweep 定时器没人管、
退出时可能向已销毁的 `webContents` 发消息。
**根因**：生命周期没有统一归属，各自散在装配代码里。
**修法**：`before-quit` 里集中：停轮询、清 sweeper、停让路探测，最后落盘
（落盘放最后，因为 `saveTo` 会刷新 `lastSeenAt`）；用 `closing` 标志防重入；
sweeper 加 `.unref()` 免得它自己拖着事件循环。
**怎么验**：e2e 的退出残留检查 + 人工看任务管理器。
**教训**：常驻定时器/子进程一律在装配处拿到"停止函数"，别等出问题再补。

## 4.5 新版本写的存档，被旧程序降级覆盖

**症状**：审查指出——注释说"版本高于支持范围时按默认值处理"，代码却照抄未来档的字段
并把 `version` 改写成 1，退出时无条件落盘。
**根因**：读盘和写盘是两个函数，中间没人记得这个档"我们没看懂"。
**修法**：`migrate` 真的回默认值，并带一个 `fromFuture: true` 诊断标记；
`saveTo` 见到它就**一个字节都不写**（连 `.bak` 也不生成，那份"备份"是从不认识的原文件复制来的）。
**怎么验**：`test/save.test.ts` 断言默认值真生效，`test/storage.test.ts` 断言写后原文件一字不变、
不产生 `.bak`。
**教训**：诊断信息（`warnings`、`fromFuture`）必须和"要不要落盘"这个决定绑在同一个函数里，
否则一定会被忘记。

## 4.6 Windows 上刚退出的进程还攥着文件句柄

**症状**：测试清理临时目录时 `rmSync` 抛 `EBUSY`。
**根因**：`force: true` 只忽略 ENOENT，不忽略 EBUSY；Electron 子进程句柄释放是异步的。
**修法**：清理包在 try/catch 里，清不掉就算了——临时目录归系统回收。
**怎么验**：e2e 稳定跑完不残留报错。
**教训**：Windows 上"删不掉临时文件"不是失败，别让它把测试整体判红。

---

## 4.7 渲染层不留 `destroy()` 是有意的

**症状**：两轮审查都提"rAF、心跳定时器、事件监听没有统一销毁出口"。
**根因**：不是遗漏——主进程用 `once('did-finish-load')` 推皮肤，页面既不 reload 也不热切换，
disposer 没有调用方。
**修法**：不写。在 `bootstrap()` 上留一段注释写清理由和"什么时候该补"（出现第二个装配点时）。
**怎么验**：注释即结论；将来加热切换或多宠物时按那段补。
**教训**：没有调用方的生命周期出口是空壳，还会给人"已经处理过了"的错觉——
项目自己的编码规则第 8 条就是为这个写的。
