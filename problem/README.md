## 每条的写法

**症状 → 根因 → 修法 → 怎么验 → 教训**。
「症状」写用户看到的原话，因为将来复现时只有这句话；「教训」只写下次能照着做的一句话，不复述过程。

## 三条通用规矩（都是从这些坑里长出来的）

1. **能用眼睛看的结论不算证据。** 透明合成、穿透、残影、焦点这类事，必须落到本机 DWM 桌面帧、
   `WindowFromPoint`、`exstyle`、F13 按键探针这类可复现的读数上；`spike/` 里那批探针就是干这个的。
2. **探针自己要先自检。** 好几轮"没差异"其实是探针测不到（单帧 1 秒 vs 400ms 事件、
   根本没把面板打开、读了个动画中间帧）。先证明探针能测到已知现象，再拿它作证。
3. **测试要测用户时序，不是测零件。** 多条检查当时是"假通过"：只比了 x 没比 y、
   依赖上一条留下的状态、在静止光标下喂了第二次坐标。逻辑测绿但没接线，也算没做。
