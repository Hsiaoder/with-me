# 测试、探针与工具链

这一份不记产品 bug，记的是**差点让我自己骗了自己**的那些事。

---

## 6.1 断言要按平台实测行为写，不能按印象写

**症状**：`test/protocol-path.test.ts` 三条路径穿越断言全错。
**根因**：以为 `app://assets/../../etc` 会原样进到解析里——实际 `new URL()` 会**规范化** `..`，
`%2e%2e` 也有自己的处理方式。
**修法**：先用 `node -e` 把真实解析结果打出来，再照着写断言。
**教训**：写"它应该拒绝"之前，先确认它到底收到了什么字符串。

---

## 6.2 检查项红一次不算数，红→改→绿才算闭环

**症状**：本轮三次改动（拖拽回弹、鼠标被扣 400ms、面板残留命中）都是
**先加检查 → 跑一次确认它是红的 → 再改 → 变绿**。
**根因**：不是 bug，是纪律。
**修法**：写不出红的检查就说明改动没法验证。
**教训**：先红后绿是"这条测试真的在看这件事"的唯一证据。

---

## 6.3 探针精度必须配得上被测量的时间尺度

**症状**：一次 A/B 实验两边读数完全一样，得出"修复无效/无差异"的错误结论。
**根因**：每次查询都新起一个 PowerShell 并 `Add-Type` 编译 C#，单帧约 1–2.8 秒，
而要看的事件是 400ms 级。
**修法**：单进程内循环采样（`watch`/`follow`），或干脆把读数放进页面里用
`page.evaluate` 轮询（`grab-probe.mjs` 毫秒粒度）。
**教训**：先量一下探针自己的分辨率，再拿它做对比实验。

---

## 6.4 别在过渡中间读 computed style

**症状**：e2e 断言「收起后面板 `display` 应为 none」，实测拿到 `flex`，而 `isOpen` 已经是 false。
**根因**：`transition: display .18s allow-discrete` 是**故意留的淡出**——布尔型属性在过渡期间
保持旧值，180ms 后才翻。断言只等了 100ms。
**修法**：`assert(open===false)` 之后再 `waitForTimeout(400)` 才读 `display`。
**教训**：读"会动画的属性"要等过 `transitionDuration`；否则测的是动画中间帧。

---

## 6.5 合成事件测不到系统层的事

**症状**：CDP 的 `page.mouse.move` 能驱动拖拽，却测不到穿透、光标形状、窗口归属。
**根因**：Playwright 的合成事件走 CDP `Input`，不移动操作系统光标、不进系统命中测试。
**修法**：这类问题必须用真输入：`SetCursorPos` + `mouse_event`（`spike/winprobe.ps1`），
读结论用 `WindowFromPoint` / `GetWindowLong(GWL_EXSTYLE)` / `GetForegroundWindow`；
测焦点用发 F13 看谁收到按键（F13 几乎没应用绑定，不会打字也不会触发动作）。
**教训**：分清"页面行为"和"系统行为"，后者只能用系统级的喂入和读数。

---

## 6.6 检查不要依赖上一条检查留下的状态

**症状**：新加一条"面板位置"检查（会把宠物挪走）之后，后面两条老检查同时红。
**根因**：它们默认"上一条已经把面板开好、光标还停在身上"，检查之间靠隐式顺序耦合。
**修法**：抽 `openOnBody()` 当前置（宠物可能正在走，所以重读命中框重试），
每条检查自带前置状态。
**教训**：检查要能单独跑。耦合在顺序上的测试，改一条坏两条。

---

## 6.7 等"装配完成"不等于等"能画面"

**症状**：换皮肤 e2e 偶发——断言 `currentSrc` 时 `videoWidth` 还是 0，或者反过来，
测试仍然通过。
**根因**：只等了 `__petDebug` 出现（那只代表装配跑完），没等首帧真的解出来。
**修法**：等 `document.querySelector('video.is-front').videoWidth > 0` 再断言。
**教训**：等状态标志不如等它带来的可观测结果。

## 6.8 shell 与编辑器的四类手滑（都真实发生过）

| 手法 | 后果 | 以后的规矩 |
|---|---|---|
| `printf` 写 `%~dp0` | bash 把 `~` 当格式符，直接报错 | 生成文件一律用 `Write` 工具或 node |
| `node -e` 里写 `'s?'?'':'path'` 三元 | 解析成空路径 → `ENOENT`，文件**没被写**（幸好失败得响亮） | 改代码用 `Edit` 工具，不用 shell 拼字符串 |
| bash 里的反引号与 `$` | 被当命令替换吃掉，写进文件的文本少了东西 | 带反引号的中文长文本绝不走 `bash -c` |
| `.ps1` 里写中文（踩了 4 次） | WinPS 5.1 按 ANSI 读 UTF-8。前三次是解析失败（报错还是乱码），**第四次更坏：脚本正常跑完，但 `$x = [int]$env:...` 被前面的乱码行顶成了空值，探针照样打印出一行像样的读数**，坐标其实一直是 0 | 脚本内容纯 ASCII；非要留中文注释就**存成带 BOM 的 UTF-8**（`EF BB BF`）。凡是探针算出来的坐标/句柄，都要有一行"读数对不对"的自证（这次靠 `aim=` 和 `actual=` 并排打印才发现） |
| 批量替换时把新旧字符串写反 | 测试文件被替换 101 处，`assert(...)` 后面全成了 `, { once: true })` | 当场 `git checkout -- <file>` 还原再重做；**批量编辑前先看清方向**，能限定唯一上下文就别用宽松匹配 |

## 6.9 `git add` 漏目录

**症状**：提交后 `git status` 还剩 4 个 `test/` 文件未提交。
**根因**：`git add -A src e2e README.md spike` 手写目录清单，漏了 `test`。
**修法**：补提交；之后要么 `git add -A` 要么逐文件明确列。
**教训**：提交后**看一眼 `git status`**；"我以为提交了"和"提交了"是两件事。

## 6.10 「系统真换了光标吗」：三次读数错位

**症状**：CSS 规则加上了、`document.body` 的类也翻对了，探针却在命中区读到系统箭头
（`h=65539`），离开后反倒读到自定义手形（`hot=9,2`）。后来又在按钮上读到一枚
**32x64 的纵向缩放手**——那玩意儿我们代码里根本没有。

**根因**：三处独立错位叠在一起。

1. **Windows 在下一次鼠标移动被处理时才换光标**。`SetCursorPos` 到位就采样，读到的是
   上一个位置的光标。修法：到点后再在同一区域里抖 1px，然后才读。
2. **`screen.getPrimaryDisplay().scaleFactor` 在这台机器上是 2，可 DIP 就等于物理像素**
   （workArea 1600×952，虚拟屏 1600×1000，要 1603 被夹回 1600）——进程没做 DPI 感知。
   拿它乘坐标会算到屏幕外。修法：不猜倍率，`[1, dpr, scaleFactor]` 挨个试，
   拿 `pet-over` 这个类当 oracle，哪个能真的走进命中区就用哪个。
3. **探针自己把面板等收起了**。顺序是「身体 → 空地 → 等 700ms → 按钮」，而离开身体的
   那一瞬 1500ms 收起倒计时就起了；走到按钮上时面板正好 `display:none`，那点变成穿透区，
   **读到的是底下那个窗口的光标**（所以冒出缩放手）。改成「量完身体就地等面板出来」之后
   还是复现了一次——连着量第二个、第三个点同样会跨过 1500ms。定稿做法：**每个待测点之前
   都重新把面板叫出来**，并在读数里同时打印该点的 `elementFromPoint` 与 `computed cursor`：
   DOM 说命中了、系统却不认，说明那点根本不在我们这扇窗里。

**怎么验**：`node spike/cursor-probe.mjs`。它同时打印 `aim=`（我们要的坐标）和
`actual=`（`GetCursorPos` 读回来的坐标），以及 `hot=`（热点）——热点等于 CSS 里写的
`9 2` 才说明真的是我们那张 hand_point，不是别的自定义光标。光标位图还会存成
`spike/out/cursor-on-pet.png` 与 `cursor-on-button.png`。
定稿读数：身体、身体↔面板空隙、按钮之间、按钮正中**四个点同一个句柄**（`hot=9,2`），
空地是 `h=65539` 系统箭头。

**教训**：操作系统口径的东西（光标、z 序、全屏状态）不能拿 DOM 的读数当证据，反过来也不行——
DOM 类加上了只证明"我们要求换"，`GetCursorInfo` 才证明"系统换了"。
探针读数要**并排打印输入和实际**，不然错位会伪装成功能失效。
还有一条：透明覆盖层的探针必须同时报「这点归不归我们」，穿透区里的光标永远来自底下的窗口。

## 6.11 工具链上的两处遗留（还没修）

1. **`.npmrc` 的 `electron_mirror` / `electron_builder_binaries_mirror`**：每条 npm 命令都警告
   "下一个大版本不再支持"。现在不影响构建，但升级 npm 后 Electron 安装可能突然变慢或失败。
   该迁到环境变量或安装脚本支持的镜像配置。
2. **不入库的 `docs/` 与 `codex-review/`**：README 的文档地图指向的文件只在你本地，
   克隆仓库的人看不到（这是你 2026-11-03 的决定，提交 `dcaa6a5` 里记了代价）。

## 6.11 淡出中途的一帧不是证据；布局要问布局

**症状**：截图里气泡和食物面板叠在一起，看着像锚点算错了。

**根因**：两件不同的事叠在一起。

1. **那一帧是淡出中途**。探针里先 `say()` 再点喂食切视图，面板变高、气泡跟着重定位，
   而 `hideBubble()` 之后还有 0.18s 的离散过渡在走——读到的是过渡中间的位置与透明度。
2. **真 bug 在别处**：横条直接 `append` 到面板上，而面板是横排 flex，于是它并排站到了右边
   （量出来 thumb.x=952，面板却只到 959）。这是结构错，不是像素错，**截图看着"有条横条"就放过去了**。

**修法**：横条和视口成一列（`.pet-food-main`），夹在两个翻页键中间；`.pet-scroll` 宽度必须等于
`thumbGeometry` 用的视口宽 236，否则比例换算对不上像素。堆叠关系不再靠看截图，
补一条 e2e 直接问布局：`bubbleBottom <= panelTop`。

**怎么验**：`test/panel-dom.test.ts` 钉结构（`.pet-scroll` 的父节点是 `.pet-food-main`）；
e2e 钉几何（面板在头顶时气泡底不许超过面板顶）。

**教训**：视觉类断言要落到**布局自己回答的问题**上（`getBoundingClientRect`、父子关系），
不是落到"我看了图觉得挺对"。一帧动画中间态能证明东西存在，证明不了它摆对了位置。
