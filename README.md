# with-me · Windows 桌面宠物

一只站在桌面上的宠物：自己按规则和权重播动画，点一下出按钮面板，点按钮换动作，
其余区域鼠标完全穿过它落到下面的窗口。角色可以整个换掉——换一只宠物等于换一个目录。

当前状态：v1 开发中，Windows 首发。macOS 只在平台层留了接口形状，没实现。

---

## 怎么跑起来

```bash
npm install          # 依赖走 npmmirror 镜像，见 .npmrc
npm run skin:test    # 生成占位皮肤的 6 段动画（色块，不需要美术素材）
npm start            # 构建并启动
```

`npm start` 之后桌面上会出现一个绿色色块。它没有美术素材是故意的——
v1 先证明架构成立，角色形象另说（见「文档」一节）。

常用命令：

| 命令 | 做什么 |
|---|---|
| `npm run typecheck` | TypeScript 检查，不产出文件 |
| `npm test` | 纯逻辑单测（29 个文件 431 条，约 1.6 秒） |
| `npm run build` | `tsc` + 复制 html/css/svg/png 与 preload。没有打包器 |
| `npm run e2e` | 真 Electron 上验播放器、面板、气泡、列表、光标、心跳、可见性子进程（49 项） |
| `npm run e2e:skin` | 真 Electron 上验「换皮肤」这条轴（3 项） |
| `npm run alpha:check` | 素材透明通道体检 |
| `npm run progress` | 重新生成 `docs/实现进度.md` |

## 怎么用起来

- **面板怎么叫出来**：**点一下宠物**才出，鼠标路过或停上去都不弹（以前是停留 400ms 自动弹，
  整屏覆盖层上那个太容易误触，2026-11-04 改掉）。再点一次收起；离开身体与面板满 1500 毫秒也自己收。
  面板默认从脚底下递出来（脚下挨着屏幕边就翻到头顶），横向以**角色的对称轴**居中，不是贴着身体左沿。
  移开宠物的一瞬间鼠标就还给桌面了，不必等面板收。
- **面板是两块，不是一块**：根节点 `.pet-panel` 铺满覆盖层、不吃命中，只当 `data-hit` 的宿主；
  里面 `.pet-actions` 按钮条 + `.pet-plate` 副板各自 `transform` 定位。
  点喂食/状态时**按钮条不消失**，副板另找自己的位置：食物列表挂在按钮条**外侧**
  （按钮在脚下时往下长、翻到头顶时往上长，中间那段永远留给宠物），
  状态读数挂在**宠物右侧**。合成一块做不到——三个锚点不共边，而外接矩形会把中间一大片
  看不见的地方圈成命中区，桌面就点不动了。设置视图仍然整块替换按钮条（那是文字行，
  旁边再挂一排按钮只会挤成两截）。再点一次同一个视图按钮 = 收回副板。
- **面板的出场动画只给按钮条**：五颗**从左到右依次弹出**，每颗比前一颗晚 55ms（档位 `--i` = 从左数第几颗，
  `panel.ts` 按按钮数量算好写进 style），收尾用带过冲的 `cubic-bezier(.34,1.56,.64,1)`——
  等价于 GSAP 的 `stagger: .055` + `back.out(1.7)`，但**没有引 GSAP**：它值钱的地方是时间线编排、
  滚动触发、物理缓动，这里只要一次性入场错落，CSS 变量就够（这仓库的规矩是无框架、手写 CSS 变量）。
  每颗沿「离宠物那一侧」浮 6px 归位，方向读根节点的 `data-side`（脚下 +6px、头顶 -6px）；
  单颗 0.22s、最后一颗 440ms 落定，和气泡淡入同一族。
  **副板（食物列表 / 状态读数 / 设置行）直接出现，不做任何动画**——2026-11-06 用户拍的板；
  以前给它配过 scale + translate + `transform-origin` 那套，274px 的卡片胀开再落定，读起来像整块板在抖。
  三条硬约束：
  ① **只用独立的 `scale` / `translate` 属性，不碰 `transform`**——那是 `place()` 每帧写的定位，
  按钮悬停也占着它，独立属性会和 `transform` 自动相乘，所以互不打扰；
  ② 只在「从 `display:none` 出来」那一次跑（`@starting-style`），前提是 **`render()` 跨视图复用按钮条**——
  节点要是每次换视图都重建，数值快照每 60 秒推一次就会把五颗重新弹一遍；
  ③ 收起只做淡出、不做反向缩回。
  关掉动画有两条出口，都是把 `.pet-panel` 上那四个旋钮拧回中性值：系统的 `prefers-reduced-motion`，
  以及 `data-no-motion`（e2e 开局就挂上它——几何断言不该和 200ms 的位移赛跑）。
  **和 qqpet 对照过**（`demo-project/qqpet/src/renderer/ui/control.ts:191-197`）：它的错峰是 JS 递归
  `setTimeout(…, 150)` 切一个类、把图标从 30px **跳**到 40px，没有缓动、没有插值，收起也没有对应动作；
  容器出现/消失本身连 transition 都没有。所以我们这套（scale + back.out + 方向位移）比它强，不照抄。
  从它那里值得拿的是**不对称的收起延时**（子菜单收起时 `opacity .2s .3s, visibility 0s .5s`、
  出现时立刻可见，为的是光标斜着移过去时中间那段还吃得到点击，`control.css:132-146`）——
  这条我们还没有，是「面板开着时移向食物格」那条路径上值得补的一课。
- **按钮**：五个图标——米饭（喂食）/ 手柄（小游戏）/ 爱心（状态）/ 齿轮（设置）/ 三点气泡（说话），
  每颗底下垫一枚 Kenney UI Pack 的 `button_round_depth_line`（CC0，**已按 A 套「品牌蓝白」重染**：
  面 `#EBF5FB` + 环 `#6990A7` + 下半圈更深的底影 `#3E718C` + 那条青内圈 `#36BDF7` 原样没动），
  图标叠在圆底上面。素材原色是中性偏紫的灰（面 `#DADCE7` L=89.6），透在桌面上看着就发暗；
  重染的推导在 `spike/color-math.mjs`、执行在 `spike/palette-recolor.mjs`，
  色值与「旧灰紫绝迹」由 `test/palette.test.ts` 钉住——重装素材会把原色盖回来，而功能测试不会变红。
  命中区是 40 见方，**图标尺寸逐枚定**（20 / 24 / 24 / 20 / 18×21）——iconfont 那几张内部留白差得远，
  一刀切 26px 时碗的筷子和齿轮的齿会戳出圆底青圈（青圈内半径 15.6px，26px 方框的墨迹半对角 18.4px），
  爱心和手柄又空出一大圈。数值由 `spike/icon-metrics.mjs` 量墨迹实迹反推，e2e 钉住这张表。
  投影只留给说话那枚白气泡，深墨的四枚不加（2× 远程桌面上只会把细描边糊出灰晕）。
  悬停时**整颗一起**放大 1.15（只放大图标会戳出圆底外沿）。
  圆底只挂在动作按钮（带 `data-id`）上——设置、列表、状态视图里的按钮各有自己的方形底板，叠两层会像画歪了。
  **圆底没有视觉选中态，这是拍板不是遗漏**：`.on` 仍然挂在当前视图那颗上（状态语义与测试靠它），
  但不画任何东西——试过一圈 `outline` 描边环，用户看后说「不要出现外面的一个黑圈」。
  也**绝不能用卡片的 `background` 简写去表意**：简写会把圆底那张图擦成 `none`，
  按钮当场露成 40×40 的正方形（真发生过，见 problem/05 §5.17）。
  图标是 `src/renderer/icons/` 里的 SVG 加 `src/renderer/emotes/` 的 PNG，文字退成 `title` 与 `aria-label`。
  小游戏与状态按下去给一个反应（播一条 click 池），功能本身留给下一版；
  喂食与设置是切视图。设置与食物列表是底板 + 方形按钮：那是文字行，浮在桌面上读不成句。
- **「说话」是调试气泡用的**：点一次按固定顺序放出台词表的下一条（正文 + 那颗回应按钮一起），
  23 条走完绕回第一条，**绕开 25 秒冷却和 idle 概率**——不然点下去没反应，看着像按钮坏了。
  顺序而不是随机，是为了逐条核对每句文案装不装得下、回复按钮压不压边。撤掉它只要删 `PANEL_BUTTONS` 一行
  和装配层那个 `if (a.id === 'talk')` 分支。
- **喂食列表**：点米饭出一排食物格子（六个吃：代币 / 白饭 / 糖葫芦 / 大闸蟹 / 火锅 / 饺子，
  48×48 正方形、一屏 4 个，视口宽 = 4×48 + 3×4 = 204；这四个数只有 `FOOD_CELL` 一个来源，
  CSS 里的字面量由 `test/config.test.ts` 反查钉住），最左最右各一枚 Kenney 箭头（`arrow_basic_w_small` / `arrow_basic_e_small`）
  翻一整屏，矩形下面有一条可以拖的横条（自绘控件，不是浏览器滚动条），到边就置灰。
  **格子里是图，不是字**（2026-11-06 换）：六张 128×128 透明 PNG 放在 `src/renderer/foods/<id>.png`，
  显示 40px（`FOOD_ICON`），名字退成悬停 title 与读屏 label——和两个翻页键同一套约定。
  图的来路是 **AI 生一张 3×2 总表 → `node tools/make-food-icons.mjs <总表>` 切图**，
  仓库里只留切好的六张，总表在 `E:\ai-pet\vibe_images\`。选这条路的理由是授权：本项目要商用直播，
  iconfont 禁商用、game-icons 要逐条署名、CC0 素材库里根本没有糖葫芦/大闸蟹这种中式吃食，
  而自产图**没有第三方授权债**。代价是三道后处理都得自己做（抠底 / 去水印 / 归一化），
  实测踩的三条坑记在 `problem/03` §3.14。
  **三块副板共用同一张 CSS 卡片**：`--plate-fill` 的板面 + 1px 深描边 + 10px 圆角 + 6px 留白，
  格子是白卡 + 8px 圆角。食物列表以前铺的是 Kenney `button_rectangle_depth_line`
  的 border-image 九宫格（四层边、只有下边多 4px 底影，所以 slice 得写成不对称的 `8 8 12`），
  2026-11-06 用户说「不想用外边框了，做成状态那种简单的」——素材已删，那套九宫格为什么必须那么写
  留在 `problem/03` §3.9 与 §3.12，别按旧描述改回去。现在全场只剩五颗圆底那一圈青内框带装饰。
  板心色只有三档来源 `--plate-fill / --hover-fill / --on-fill`，
  再加一档 `--scroll-fill`（`#607580`，比环深一档才压得住 5px 的细条）画那条横条——四档都在 H=232 这一条阶梯上。
  副板的投影**只在下边**（`box-shadow: 0 6px 10px -4px`：负 spread 先把阴影矩形往里收 4px，10px 级的模糊就够不到上沿）。
  透明置顶窗里 CSS 模糊是实打实压在桌面上的，以前 `0 2px 8px` 那一版板顶外沿实测还有 alpha 12/255 的灰雾（读法见 `spike/foods-shot.mjs` 的向外扫描）。
  点某一格**播它自己那一条**「吃」动画：`Food.anim.name` 会拿去 `pickNamed` 查皮肤实际有没有这一口，
  有就按名字播，**没有就回落到 click**（绝不随机给一口别的——播错的那口会假装它吃的是别的东西）。
  自带的 block 皮肤故意只做 `rice` / `hotpot` 两口，e2e 于是同时覆盖命中与回落两条路
  （以前这里只递池名，所以点火锅可能播到白饭的吃相，见 problem/03 §3.13）。
  **正在吃饭时任何动作都不打断这口**（用户拍的板），2026-11-06 起**连拖拽也不算例外**：
  点身体只弹菜单、点小游戏/状态也不换动画，拎着走的时候吃相继续演完——
  拖拽的反应是**位置立刻跟着手走**，不是换一条「被拎着」的姿势。
  台词、菜单、养成数值照旧走，所以「不打断动画」不等于「没反应」。
  格子里是图（六个吃各一张，来源与后处理见上面「喂食列表」那条与 `problem/03` §3.14）；
  `Food.anim` 存的是皮肤里的 clip 名（ascii slug），
  素材源里的中文原名记在切片脚本的映射表里。**选完不收**（2026-11-05 改）：列表和五颗按钮一起留着，
  用户的手就停在这块区域上；以前整块收掉时那块像素不再归宠物，
  光标当场变回系统箭头（交互区只算看得见的那几块）。老理由「列表压住宠物看不到它吃」在两块拆分以后
  已经不成立——副板永远长在按钮条**外侧**（e2e 钉着不许压到身体框）。
  收起交给三种手势：离开满延时、再点一次喂食、点一下宠物；**吃饭期间延时会重新上弦，不自己收**。
  **但列表留着不等于能连喂**：这一口没吃完时整列格子 `disabled` + 置灰 + `not-allowed` 游标，
  饭后自己解锁（用户拍的板）。拦截靠 `disabled` 本身而不是 CSS 骗眼睛——Chromium 不给
  disabled 按钮派发 click，e2e 就用程序化 `.click()` 绕过 Playwright 的 enabled 等待来验这一条。

  **拖拽不开口**：话挂着的时候把人拎起来，气泡当场收掉，而且拖拽本身不再有台词——
  「被拎起来必回一句」和「拖拽时气泡要消失」是冲突的，用户 2026-11-05 选了后者，
  `TALK_LINES.drag` 那一档一起删掉，不留走不到的路径。
  底图是 `src/renderer/emotes/bubble.svg`——**圆角矩形 + 底部居中的三角尾巴**，内腔填实心白。
  形状的前四版：SVG Repo 那颗正圆 + 尖（`E:\ai-pet\svg\归档-未采用\chat-speech-bubble-svgrepo-com.svg`，
  量出来重画、路径没搬——它的授权页两次 429，商用条款没核到原文，所以只借形状与比例）、
  iconfont 的聊天气泡（尾巴歪左下、下沿是平的）、肥皂泡（没尾巴，所以不指宠物）、
  Kenney Emotes 的空气泡位图（CC0，经 `spike/emote-thin.mjs` 削描边 + `spike/emote-shorten.mjs` 删中段得到 32×32，CSS 放大 5 倍显示后

  2× 远程桌面上就是「边缘很模糊」，那才是换矢量）。换矢量没有「整数倍才不糊」这条约束。
  量的办法：`spike/bubble-shape.mjs` 逐行问 `isPointInFill` / `isPointInStroke` 并打印**空腔段**
  （参考图的腔是透明的、我们的腔是实心白，判据得写「不是环色」而不是「没着墨」），
  `spike/bubble-ab.mjs` 并排渲染看图对一遍。
  现在这一版是**矩形**，因为圆腔里塞矩形文字块总是白掉一圈：viewBox 440×320 → 显示 **220×160**，
  中线矩形 x 6..434 / y 6..246、圆角 36，尾巴 base 68、尖在 (220,306)。
  环是**描边**画的，粗细就是 `stroke-width` 一个数：12 单位 → **6 CSS px**
  （历史 18.3 → 9.2 → 6；再往下别低于 4px，2× 远程桌面上会开始发虚）。
  画法必须**一条闭合轮廓**（底边 → 下尾巴 → 回底边 → 圆角绕一圈）：分开画圆角矩形和三角尾巴，
  矩形那条底边描边会横穿尾巴根部，看起来像尾巴被一道线封口。
  内腔 = 中线内缩半个环 → CSS x 6..214、y 6..120、圆角 15；内容块「文字 150×60 + 缝 4 + 按钮 150×22」
  居中 → 顶 20、底 **106**（`BUBBLE_INNER_BOTTOM`，历史 120→180→152→134→106），上下各留 14。
  文字区从 110 放宽到 150，24 字排得更松（9 字一行时不再断出孤零零的尾巴行）。
  几何不抄数字：`test/config.test.ts` 从素材读 viewBox 与 stroke-width，钉住「显示比例 = 素材比例」
  「环厚 = `BUBBLE_RING_W`」，再用 `BUBBLE_CAVITY` 验内容块四角（含圆角那块）。
  矢量**不能**开 `image-rendering: pixelated`——那是格子画位图的渲染方式，套到矢量上会把圆角拉成阶梯
  （这条和「底图必须是 .svg」一起由测试钉住）。正文上限 24 字、超出截断加省略号。
  每句台词配一条主人的短回复，显示在气泡底部那颗按钮上（上限 5 个汉字宽），**点一下气泡收掉**。
  **永远在宠物上方**：面板在头顶时串序是 屏幕顶 … 气泡 → 面板 → 宠物 → 地面。
  头顶放不下时**让气泡越出屏幕上沿**——覆盖层只盖住工作区，窗口外的部分天然被裁掉，
  把宠物拖下来它就自己回来。以前夹住屏幕顶，结果宠物贴顶时气泡整个压回头上。
  光标压在气泡上会续命，但停在气泡上**不算**「在使用面板」，不会把按钮叫出来。
- **拖拽**：按住宠物可以拖到桌面任何位置，**左右都能拖到身体贴住屏幕边**（夹的是身体外沿，
  不是画布外沿；那截空白由皮肤 `bodyBox` 算出来，换皮肤自动跟着变）。移动超过 4px（`DRAG_START_PX`）
  那一刻就换上「被拎着」动画，松手回到待机继续自己的动作循环——动画挂在**拖起来**那一刻，不是挂在松手。
  **唯一的例外是吃饭**（2026-11-06 改）：嘴里那口还在演时，拖拽只挪位置、不换姿势，
  吃相一路演完，格子也一路灰着（原先「被拎起来必须有反应」那条例外删掉了，见 problem/05 §5.23）。
  **正在吃饭时这一条让位**（2026-11-06 用户拍的板）：吃相一路演完，拖拽只挪位置，
  拎着走的时候它还在嚼；于是格子也一路灰着，松手不提前解锁（见 problem/05 §5.23）。
  同一刻**菜单和气泡都收掉**：它们一路跟着宠物飘，不是用户此刻要用的东西。
  没到 4px 就松手算「点一下」，走 `click` 池的动画（那一档的台词还没配）。
- **养成数值**：四条，全在 `src/shared/stats.ts` 里按「每分钟」口径定义，0–100 浮点、显示取整。
  饥饿 70 起、−0.8/分；心情 70 起、−0.5/分，**连续 30 分钟没人理涨到 −1.2/分**；
  体重 50 起、**不随时间自然下降**（只能靠活动消耗，喂下去的热量留着——这是它唯一的效果来源）；
  亲密度 0 起、−0.2/**天**，是长期账。每条都同时有「哪个动作抬它」和「低了它演什么」，缺一条就不该存在：
  饥饿 <30 走 `hungry` 台词档、心情 <30 走 `blue` 档（和 `idle` 一样要过「闲够 20 秒 + 35% 概率」那道门，
  所以它不会变成复读机）。抬它的路径：喂食按食物给 6~22 饥饿与 0.4~1.5 热量、逗玩 +6 心情、
  **点气泡那颗回应按钮 +2 心情 +0.3 亲密**（你理它了）、每天第一次打开面板 +0.2 亲密。
  两道防刷闸（qqpet 恰恰没有：它的逗脸和小游戏是固定收益无冷却，连点就能刷满）：
  同类动作 10 分钟内第二次收益减半；饥饿 >90 再喂也减半（吃不下）。
  **离线按在线速率的 30% 补算，每条最多损失 30 点，体重离线不掉**——
  全额补算等于惩罚关电脑，完全不补又让数值失去意义。时钟在**主进程**（每 60 秒结算一次并落盘），
  渲染层只上报动作、只订阅快照：数值是长期账，不该因为页面重载丢掉结算起点。
  **等级是另一本账**：`exp` 只增不减、进存档（可选键，老档没读就当 0），等级 = `floor(exp/10)+1`
  是**算出来的读数、不入库**（入库就有两份真相）。经验来源：逗玩 0.4、回复 0.3、每天第一次打开 0.2、
  **喂食 0.2**——按拍板「喂食也算照顾」，但它**只进经验、不动那条亲密条**（亲密只认陪伴类动作，
  平衡早就调好了，不该被这个决定顺带改掉）。按现速率一天认真陪约 3.7 点 ≈ 三天一级。
  只增不减是刻意的：冷落几天亲密条会掉，但「你陪过它多少次」不该被抹掉，所以**等级不会退**。
- **涨值飘字**：动作让四条数值涨了，宠物旁边飘出「饥饿 +14」那样的小芯片，1.1 秒（`FLOAT_MS`）
  自己掉。观感照 qqpet（它的 +N 画在 `pet/float/mood.swf` 里，我们这边是 `src/renderer/float.ts`
  + `floatAnchor` 自己那一套）。四条规矩：
  **等这次动作自己的动画演完再冒**（点完喂食就冒数字像结算回执；等它把这一口咽下去再冒才是
  「它吃了所以涨了」。攒不攒的判据是 `requestActionClip` 只挂在**会报数值的动作**上——点气泡回应、
  每天第一次开面板没有自己的动画，压着等就变成「理了它却没反应」；中途被拎起来也不冒，
  落地那一拍一起放出来）、**只有涨的飘**（自然衰减每分钟都在动，跟着飘就是刷屏，
  何况衰减本就不该被注意到）、**经验不飘**（0.2 / 0.3 的小碎步，会把要紧的那两条挤走）、
  四舍五入成 0 的不飘（`+0.0` 比不飘更怪）。
  **每条数值各有各的颜色与字号**：饥饿 焦糖橙 `#a04a00` / 14px、心情 玫红 `#aa295f` / 13px、
  体重 紫 `#6938a7`、亲密度 松绿 `#007840`（后两条走基类 12px）。颜色只回答「这是哪条」，
  不当警报——体重原先用靛蓝，因为状态条那三档报警色里已经有一支蓝（蓝=这条快满了），
  同一屏里一个色相不能有两副面孔，所以挪到紫。四支都在白芯片压着近黑桌面混出来的最暗底
  （≈ `#ededed`）上量过对比度 ≥4.5:1（`node spike/float-color.mjs`），色值由 `test/config.test.ts` 钉住。
  **站左边**优先——状态栏常年挂右边、气泡在头顶、按钮条在脚下，头的左边常年是空的；
  状态栏翻到左边时它改站右边（`floatAnchor`）。
  这一层**不挂 `data-hit` 且 `pointer-events:none`**：点不着、只活一秒的东西不许把鼠标接住
  （problem/01 §1.15 那条老规矩）；**清理归 JS 定时器**，不归 `animationend`——系统开「减少动效」时
  CSS 把动画整条关掉，那条事件永远不来，字就会堆在屏幕上不掉（problem/05 §5.21）。
- **状态栏**：点面板的「状态」按钮，竖着一条弹在宠物**右侧**（`statsAnchor`；右侧放不下才翻到左边，
  夹过来会压住宠物，那是气泡踩过的同一个坑，见 problem/05 §5.10）。
  从上到下：`姓名 小鲸`、`性别 ♀`、`等级 Lv.1`（**一行读数，不带进度条**——2026-11-05 用户拍的板：
  饥饿心情低了你能喂能逗，等级攒到多少你什么都做不了，画条反而像「这项快满了」；
  累计经验挪到悬停的 title 里），然后四条带数值的进度条
  （颜色 >60 蓝、>20 黄、否则红，**同时写着数字**，色觉障碍或壁纸花的时候还能读）。
  等级行刻意不挂 `.pet-stat`——那个类专指「一条数值读数」，报警配色与「数几条」的测试都靠它。
  **没有返回按钮**——收起靠再点一次状态键
  或离开满 5 秒自动收。性别是**一枚可点的符号**（U+2640/2642，粉=雌、蓝=雄），
  点一下换到另一档并当场落盘；改名要键盘输入而这扇窗默认不收键盘，所以名字仍是只读。
  前两行用 `.pet-stat-line`，和读数行同列但**不带 `.pet-stat`**——那个类专指「一条数值读数」，
  单测与 e2e 都按它数条数，混用会让「快照没到就不画四条」那条断言数到假读数。
- **存档 v2**：`version: 2`，新增 `identity{name,gender}` 与四条数值。v1 的 `stats` 是占位形状
  （`{hunger,mind,clean,mood}` 全 80，且没有任何生产调用方改过它），迁移时 hunger/mood 沿用、
  mind/clean 丢弃。坏档一律回退默认值并记 `warnings`，永不抛异常。
- **光标**：交互区内是同一枚 Kenney `hand_point`（CC0，热点 (9,2) 是指尖，按 PNG 的 alpha 实测量出来的），
  值只有 CSS 变量 `--pet-cursor` 一份。**交互区 = 身体框、开着的面板、开着的气泡三者的外接矩形**——
  取外接矩形而不是并集，是为了**连续**：身体到面板之间那截、按钮之间那 8px、面板与气泡之间那 12px，
  按各自矩形判都会落空，手形会一路闪回桌面的样子。都收起后区域缩回只剩身体。
  代价说清楚：面板开着时那截看不见的空隙，点击归我们（按下不反应）。但"算不算有人在使用"
  仍然只问 DOM 命中——停在空隙里不算活动，1500ms 收起照旧跑，所以吞点击的时间有上界。
  qqpet 把光标挂在 `html,body` 上（它的窗就只有宠物那么大，整窗等于交互区），
  我们是整屏穿透窗，只能跟着区域开关。
- **自主行为**：没人理它超过 20 秒，它开始按皮肤 `weights` 自己在待机 / 转身之间抽。
  平行走动（`move`）暂时不在自主池里——这版形象更适合待在原地做小动作，想放回来把
  `AMBIENT_POOLS` 里的 `'move'` 加回去就行，走动那套素材和皮肤契约都没动。
- **可见性设置**：面板里的「设置」按钮有两档——「全屏时」「放映时」，各选「陪我」或「隐藏」，
  **默认都陪我**。判据是 Windows 的通知状态（独占全屏 / 演示模式）加上"前台窗口是否铺满整块屏"，
  后者带一张系统外壳排除表，否则锁屏界面会被当成有人在全屏。改了立刻写进存档，不用退出。
- **命中区可视化**：`Ctrl+Shift+点身体` 画出红色身体框，再点一次消失。排查
  「鼠标停在身上没反应」这类问题用得上。（不用 F9：这扇窗故意不可聚焦，收不到键盘事件）

存档在 `%APPDATA%\with-me\save.json`，每次退出时写。用户自己放的皮肤放
`%APPDATA%\with-me\skins\`，同名时优先于内置。

## 怎么自定义皮肤

一个皮肤 = 一个目录，里面一份 `manifest.json` 加若干带透明通道的 webm。
完整契约见 [`docs/superpowers/specs/2026-11-02-skin-pack-contract.md`](docs/superpowers/specs/2026-11-02-skin-pack-contract.md)，
这里是速查版。

```
skins/<皮肤id>/
  manifest.json
  animation/
    idle/    patrol.webm  patrol2.webm
    turn/    left.webm
    move/    step.webm
    click/   tapped.webm
    drag/    pulled.webm
```

动画文件的地址由**池名和文件名**拼出来：`animation/<池>/<名字>.webm`。
名字就是文件名（不含后缀），不是数组下标。

### manifest 最小可用版

```jsonc
{
  "formatVersion": 1,
  "name": "我的宠物",
  "canvas": { "w": 640, "h": 360, "feetY": 330 },
  "bodyBox": { "x": 200, "y": 50, "w": 240, "h": 285 },
  "pools": {
    "idle":  ["patrol", "patrol2"],
    "turn":  ["left"],
    "move":  ["step"],
    "click": ["tapped"],
    "drag":  ["pulled"]
  }
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `formatVersion` | 是 | 只能是 `1`。不认识就拒绝装载并提示升级程序，不猜 |
| `name` | 是 | 展示用 |
| `canvas` | 是 | 必须 `640×360`；`feetY` 在 1–359 之间 |
| `bodyBox` | 是 | 身体占的画布矩形，命中判定和贴边的依据，必须完整落在画布内 |
| `pools` | 是 | 五个必需池 `idle/turn/move/click/drag` 一个都不能少，每池至少一条 |
| `weights` | 否 | 池级权重，只影响自主走动选哪个池；不写等于全 1 |
| `animationMeta` | 否 | 单条动画的 `loop` / `mirrorable` / `bodyBox` 覆盖 |
| `hotspots` | 否 | v2 互动用，v1 只透传 |

池名与动画名只允许 `[a-z][a-z0-9_-]`（池名 ≤32、动画名 ≤40）。它们要当文件名用，
也要拼进 URL，中文和大小写混用在 Windows 上都有坑。

### 三条素材合同

1. **动画周期必须整除素材时长。** 每段动画从标准正面姿势起步、末尾回到这个姿势，
   这样任何一段播完都能无缝接回待机。**不要把首帧复制一份当末帧**，那会多停一帧。
   周期取 1.6 秒这种不整除 4 秒的值是最常见的错法：末帧停在半空，每次接缝就跳一下。
2. **角色任何一帧都不许出 `bodyBox`。** 出框的后果是命中判定错位——鼠标停在
   看得见的身上不弹面板，停在看不见的框里反而弹。原地动作（呼吸、摆尾、跳跃）写在
   动画里；**位移（走路、跑动）不写在动画里**，由程序移动整个舞台实现。
   轮廓剧变的动作（趴下、缩成一团）要在 `animationMeta.<名>.bodyBox` 里单独给框。
3. **编码必须是 VP9 + alpha 的 WebM：**

   ```bash
   ffmpeg -y -i 输入.mov -vf "colorkey=0x0000FF:0.30:0.05,format=yuva420p" \
     -c:v libvpx-vp9 -pix_fmt yuva420p -crf 8 -b:v 0 -auto-alt-ref 0 -row-mt 1 -an 输出.webm
   ```

   不显式写 `-c:v libvpx-vp9` 会**静默丢掉 alpha 通道**——画面看着正常，背景变成
   一整块不透明矩形。`-auto-alt-ref 0` 也不能省。

### 交付前必做

```bash
npm run alpha:check skins/mine/animation/idle/patrol.webm
# 期望：{"frames":8,...,"bgAlphaMax":0,"haze":false}
```

`haze:true` 说明背景没抠干净，或者角色跑出了 `bodyBox`。这个工具分不清这两种，
两种都要排查。调小 `colorkey` 的相似度容差（第二个数，0.30 → 0.20）重导。

## 已知限制

- **只认启动时那一块屏的主工作区**：覆盖层的尺寸、系统光标原点、渲染层的运动边界都只在建窗时读一次
  （`src/main/windows.ts`）。运行中改主显示器、改分辨率或缩放、任务栏自动隐藏导致工作区变化、
  显示器断开重连，这三者会失去一致——表现是宠物贴边位置不对、命中框和真实光标错位、或覆盖层盖不住新的工作区。
  **v1 的处理办法是重启应用。** 多显示器与 `display-metrics-changed` 监听留到下一轮（复审 #3 P2）。
- **没有 CSP**：页面目前只加载本地 `app://` 资源、DOM 全部走 `textContent`，没有直接注入点，
  所以这不是当下可利用的漏洞；但等加入富文本或第三方皮肤元数据时就该补上（复审 #3 P2）。

## 常见故障

| 现象 | 原因与处理 |
|---|---|
| 宠物周围有一块灰色/蓝色矩形底 | 素材 alpha 没做好。跑 `npm run alpha:check`；确认编码命令里有 `-c:v libvpx-vp9` 和 `-pix_fmt yuva420p` |
| 鼠标停在宠物身上没反应 | `Ctrl+Shift+点身体` 看红框和看得见的轮廓对不对得上。对不上就是 `bodyBox` 写小了，或者动画把角色画出了框 |
| 面板弹出来但点不动按钮 | 穿透租约被放开了。看主进程控制台有没有 `[fullscreen]` 或 IPC 报错；确认渲染层心跳还在发（`window.__petDebug.grabSends` 应该持续增长） |
| 整块屏幕点不动 | 兜底机制会在 500 毫秒后自动恢复穿透。如果持续发生，说明渲染层在反复请求接住鼠标，检查交互区判定 |
| 全屏看视频/玩游戏时被宠物盖住 | 让路探测没起来。检查 `powershell.exe` 是否被安全策略拦住，主进程控制台会有 `[fullscreen]` 错误 |
| 换皮肤没生效 | 看控制台有没有「找不到皮肤」警告。用户皮肤要放在 `%APPDATA%\with-me\skins\<id>\`，且 `save.json` 的 `skin` 字段要等于目录名（小写字母数字下划线短横线） |
| 动画接缝处跳一下 | 素材周期没整除时长，见上面第 1 条合同 |
| 启动后什么都没有 | 打开 DevTools 看控制台。皮肤装载失败时屏幕上会出现红色错误框；如果连错误框都没有，检查 `dist/preload/index.cjs` 是否存在 |

一句话架构：Electron 双进程 + 一个共享纯逻辑层。主进程只做建窗、穿透开关、光标推进、
焦点切换四件事（全部收在 `Platform` 接口后面），皮肤校验、命中判定、面板收起计时、
行为调度、播放器抽象全是不依赖 Electron 和 DOM 的纯函数，所以能被单测覆盖。
素材走自定义协议 `app://`，因为 Chromium 禁止 `file://` 页面 import ES 模块。

## 已验证的关键事实

- 整屏透明覆盖层 + **保留硬件加速**在真机成立：宠物框外 580 万像素不透明数为 0，
  真实屏幕差分意外变化为 0，24fps 不掉帧，CPU 稳态 1.4%。
- **不能用 `<video loop>`**：实测每次循环回到起点都要重新缓冲。重复播放由行为层
  再调一次 `play()` 实现。
- 主进程 ESM 入口不能写顶层 `await`，会与 `app.whenReady()` 互等死锁。
- `ipcMain.on` 必须早于 `loadFile`，否则渲染层首帧消息静默丢失。

详细数据见 `spike/README.md`。
