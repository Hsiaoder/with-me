# 皮肤包契约 · formatVersion 1

| 项 | 值 |
|---|---|
| 读者 | 想做皮肤的人（不需要会写代码），以及实现装载器的开发者 |
| 状态 | 契约已定。校验器在实现计划 Task 5 落地，落地前以本文为准 |
| 关联 | [v1 功能规格](2026-11-02-desktop-pet-v1.md) · [架构大纲](../../架构大纲.md) |
| 参考实现 | 仓库内置的占位皮肤 `skins/block/` |

**一句话**：一个皮肤 = 一个目录，里面一份 `manifest.json` 加若干带透明通道的 webm。程序不认角色名，只认这个目录结构。

---

## 1. 目录结构

```
skins/<皮肤id>/
  manifest.json
  animation/
    idle/    patrol.webm  patrol2.webm
    turn/    left.webm
    move/    step.webm
    click/   tapped.webm
    drag/    pulled.webm
    <自定义池>/  <任意名字>.webm
```

- `<皮肤id>` 是目录名，装载时由用户指定路径，manifest 里没有这个字段。
- 动画文件的**地址由池名和文件名拼出**：`animation/<池>/<名字>.webm`。名字就是文件名（去掉后缀），不是数组下标。
- 自定义池允许，程序不认识就只当备用池用，不会报错。

## 2. manifest 完整示例

```jsonc
{
  "formatVersion": 1,
  "name": "缓存",
  "author": "你",
  "canvas": { "w": 640, "h": 360, "feetY": 330 },
  "bodyBox": { "x": 200, "y": 50, "w": 240, "h": 285 },
  "pools": {
    "idle":  ["patrol", "patrol2"],
    "turn":  ["left"],
    "move":  ["step"],
    "click": ["tapped"],
    "drag":  ["pulled"]
  },
  "weights": { "idle": 5, "move": 3, "turn": 1, "click": 1, "drag": 1 },
  "animationMeta": {
    "left":    { "mirrorable": false },
    "tapped":  { "bodyBox": { "x": 210, "y": 90, "w": 220, "h": 245 } }
  },
  "hotspots": {}
}
```

## 3. 字段规则

| 字段 | 必填 | 规则 | 不合规的后果 |
|---|---|---|---|
| `formatVersion` | 是 | 整数。程序只接受支持范围 `[1, 支持上限]` | 不认识 → 拒绝装载并提示升级程序，**不猜** |
| `name` | 是 | 展示用，任意文本 | 缺失 → 拒绝 |
| `author` | 否 | 展示用 | — |
| `canvas` | 是 | **必须等于 `{w:640, h:360}`**；`0 < feetY < 360` | 尺寸不符 → 拒绝（素材尺子锁死，否则所有皮肤的坐标体系会乱） |
| `bodyBox` | 是 | 必须完整落在画布内：`x≥0, y≥0, x+w≤640, y+h≤360` | 越界 → 拒绝 |
| `pools` | 是 | 池名 → 动画名数组。五个必需池 `idle/turn/move/click/drag` **一个都不能少**，每个池至少一条 | 缺池 → 拒绝，错误里逐条列出缺哪个 |
| `weights` | 否 | 池名 → 正数。缺省全为 1 | 出现负数或非法池名 → 拒绝 |
| `animationMeta` | 否 | 动画名 → 元数据。键必须是 `pools` 里出现过的名字 | 出现孤儿动画名 → 拒绝（说明 manifest 自己前后不一致） |
| `hotspots` | 否 | v1 只透传不解释，留给 v2 互动 | — |

### 3.1 `loop` 的缺省规则

不用逐条写 `loop`，程序按池名给默认值；写了 `animationMeta.<名>.loop` 就以你写的为准：

| 池 | 缺省 | 为什么 |
|---|---|---|
| `idle`、`turn`、`move` | `true` | 状态性动作，要能一直挂着 |
| `click`、`drag` 及所有自定义池 | `false` | 反应性动作，播完就该回待机 |

所以第 2 节示例里的 `left` 只写了 `mirrorable`——它的缺省（`turn` 池 → 循环）正是想要的，不必重复。`mirrorable` 缺省 `false`。

### 3.2 `weights` 只管选池，不管选条

`weights` 是**池级**权重，用在自主走动时"下一步选哪个池"；同一个池内有多条动画时**均匀随机**，不支持逐条权重。这样契约简单，也够 v1 用。不写 `weights` 就等于全 1。

### 3.3 命名规则（会拼进文件路径和 URL，所以从严）

| 对象 | 允许 | 长度 | 为什么 |
|---|---|---|---|
| 池名 | `[a-z][a-z0-9_-]*` | ≤ 32 | 保留字 `idle/turn/move/click/drag` 是必需池 |
| 动画名 | `[a-z][a-z0-9_-]*` | ≤ 40 | 要当文件名，也要拼进 `app://skin/<池>/<名>.webm`。中文、空格、大小写混用在 Windows 与 URL 转义上都有坑；`/\:*?"<>|` 直接是非法文件名字符 |

## 4. 素材规格

### 4.1 一条硬合同：动画周期要整除素材时长

**每段动画都从标准正面姿势起步，并在末尾回到这个姿势**，这样任何一段播完都能无缝接回待机，也意味着你可以用同一张正面图起稿所有动画。

准确说法是：**动画周期必须整除素材时长**。24fps、4 秒的素材共 96 帧（`t` 从 0 到 3.958），周期取 1s / 2s / 4s 都能整除，末帧正好停在首帧前一步，接回去是连续的。

**不要把首帧复制一份当末帧**——那会让接缝处多停一帧，看起来像卡了一下。

周期取 1.6s 这种不整除的值是最常见的错法：末帧停在半空，每次循环接缝就跳一次。这条装载器**查不出来**（它不知道你的周期是多少），只能靠作者自查，所以列在第 7 节清单里。

### 4.2 画面与坐标

| 项 | 要求 |
|---|---|
| 分辨率 | 640×360，逐像素固定 |
| 脚底 | 站在 `feetY` 这条线上（默认 330）。所有动画都要遵守，否则宠物会"浮起来"或"陷进桌面" |
| 朝向 | 默认朝右。朝左由程序镜像 `mirrorable: true` 的动画，**不需要**单独出素材 |
| 内容范围 | **任何一帧的可见像素都必须落在 `bodyBox` 内**，否则要么改动画、要么给那条动画单独写 `bodyBox` 覆盖 |

最后一条是实测踩出来的。占位皮肤第一版让色块在动画里左右平移，结果角色跑出了命中框——鼠标停在看得见的身上不弹面板，停在看不见的框里反而弹。命中判定和面板位置全部以 `bodyBox` 为准，所以：

- **原地动作**（呼吸、摆尾、眨眼、跳跃）写在动画里。
- **位移**（走路、跑动）不写在动画里，由程序移动整个舞台实现。
- 轮廓剧变的动作（趴下、缩成一团、躲起来）必须在 `animationMeta.<名>.bodyBox` 里给出该动画的实际框。

### 4.3 编码

| 参数 | 值 | 不这样会怎样 |
|---|---|---|
| 容器/编码 | WebM + **VP9**，命令里必须显式写 `-c:v libvpx-vp9` | 让 ffmpeg 自己挑编码器会**静默丢掉 alpha 通道**，画面正常但背景变成一整块不透明矩形 |
| 像素格式 | `yuva420p` | 走别的路径会把 alpha 做色度二次采样（降分辨率存储），边缘发虚 |
| `-auto-alt-ref` | `0` | 开着会让透明帧被参考帧污染 |
| `-b:v` | `0` + `-crf` | 固定码率会挤掉 alpha 的预算 |
| `-crf` | 8（质量优先）～ 20（体积优先） | 越高边缘越糊 |
| 帧率 | 建议 24fps | 不是硬要求，播放器按时间轴走 |
| 时长 | 建议 2–8 秒 | 太长对内存和切换接缝都没好处 |
| 体积 | 建议单段 ≤ 2MB，整个皮肤 ≤ 20MB | — |
| 音轨 | 不要（`-an`） | 播放时会被静音，白占体积 |

推荐命令（`tools/make-test-skin.mjs` 用的就是这套）：

```bash
ffmpeg -y -i 输入.mov -vf "colorkey=0x0000FF:0.30:0.05,format=yuva420p" \
  -c:v libvpx-vp9 -pix_fmt yuva420p -crf 8 -b:v 0 -auto-alt-ref 0 -row-mt 1 -an 输出.webm
```

### 4.4 生成流程建议用蓝幕，不是绿幕

如果你用 AI 或实拍生成素材，背景建议 `#0000FF`。**不要用绿幕**：角色身上带荧光绿部件时，绿幕会把那部分一起抠掉。蓝幕相对安全，但仍要保证角色身上没有接近纯蓝的区域。

这是**流程建议**，不是交付要求——交付物必须是已经抠好、带透明通道的 webm。

## 5. 透明通道体检

体检**由命令行工具在交付前跑，装载时不跑**。原因：体检要调 ffmpeg 解码，而 `ffmpeg-static` 是开发依赖，生产代码不许依赖它，更不该为了体检让用户多背几十 MB。所以这一关是发布闸门，不是运行时保险。

判据：把 `bodyBox` 之外的区域当作背景，统计这些像素的 alpha。

| 判据 | 阈值 |
|---|---|
| 背景区 alpha 最大值 | ≤ **8** 才算干净；超过即判定为"灰雾残留" |
| 抽帧步长 | 每 12 帧取一帧（24fps 素材约每 0.5 秒一帧） |

**为什么抽多帧而不是只看首帧**：角色在动画里平移时，首帧常常刚好落在 `bodyBox` 内，后面的帧才越界，只查首帧会给假阴性。这条是实测踩出来的。

命令（皮肤作者需要仓库环境，或请程序维护者代跑）：

```bash
npm run alpha:check                              # 体检内置皮肤的全部动画
npm run alpha:check skins/mine/animation/idle/patrol.webm
# 输出：{"frames":8,"bgSamples":162000,"bgAlphaMean":0,"bgAlphaMax":0,"haze":false}
# haze:true 时退出码 1，说明抠像容差太宽，调小 colorkey 的 similarity 重导
```

**注意这个工具分不清两种情况**：背景没抠干净（有灰底），和角色跑出了 `bodyBox`（命中框漏判）。两者都表现为"框外有可见像素"，所以报 `haze:true` 时两种都要排查。

## 6. 校验会拒绝什么

装载失败时程序**一次列出全部错误**（不是改一个报一个），并且不会回退到默认皮肤——静默换皮会让用户以为皮肤加载成功了，然后来问"为什么我的宠物有块灰底"。

下面这些是实际输出的字符串，来自 `src/shared/skin.ts` 与 `src/main/skin-store.ts`：

| 错误信息 | 触发条件 |
|---|---|
| `不支持的皮肤格式版本 formatVersion=2，本程序支持 1` | `formatVersion` 超出支持范围 |
| `画布尺寸必须是 640x360，实际 512x512` | `canvas.w/h` 不符 |
| `canvas.feetY 必须是 1 到 359 的整数，脚底要真的落在画面内` | `feetY` 越界 |
| `bodyBox 越出 640x360 画布` | 默认身体框出画布 |
| `池名「睡 觉」不合法：只允许小写字母开头的 a-z0-9_-，最长 32` | 违反命名规则 |
| `pools.idle 含非法动画名 "Jump Once"：…，最长 40` | 违反命名规则 |
| `pools.turn 是空池` | 池存在但一条动画都没有 |
| `weights.sleeping 指向 pools 里不存在的池` | 权重表与池表不一致 |
| `animationMeta.jumped 在 pools 里找不到对应动画` | 元数据指向不存在的动画 |
| `找不到皮肤清单：…manifest.json` | 目录里没有 manifest |
| `皮肤清单不是合法 JSON：…` | JSON 语法错误 |
| `缺少必需动画池：turn、drag` | 必需池缺失 |
| `找不到素材文件：animation/turn/left.webm` | manifest 写了名字但文件不存在 |
| `必需池里没有一条素材真正存在：drag` | 必需池的素材全被上一条剔光了 |

透明通道相关的判定不在这张表里——它由第 5 节的命令行工具给出，不在装载时执行。

## 7. 作者自查清单

- [ ] 目录是 `skins/<id>/manifest.json` + `skins/<id>/animation/<池>/<名>.webm`
- [ ] `formatVersion` 写 `1`
- [ ] 五个必需池都有，且每个池至少一条动画
- [ ] 每条动画的名字 = 文件名（不含 `.webm`），全小写 ASCII
- [ ] `canvas` 是 `640×360`，`feetY` 在 0–360 之间
- [ ] `bodyBox` 完整落在画布内
- [ ] 动画周期整除素材时长（见 4.1），且没有把首帧复制成末帧
- [ ] 角色在所有帧里都不出 `bodyBox`（出框就改动画或写 `bodyBox` 覆盖）
- [ ] 位移不写在动画里
- [ ] 编码命令里有 `-c:v libvpx-vp9`、`-pix_fmt yuva420p`、`-auto-alt-ref 0`
- [ ] `npm run alpha:check` 每段都 `haze:false`
- [ ] 素材里不含需要联网的资源、不含第三方版权美术

## 8. 版本策略

- `formatVersion` 只增不减。加**可选**字段不升版本；改字段含义、改必需池、改画布尺寸一律升版本。
- 程序声明支持区间 `[1, 支持上限]`。遇到更高版本直接拒绝并提示升级，绝不"尽力解析"——半懂地装载一个不认识的皮肤，坏起来比不装更难查。
- 破坏性变更要同时更新本文与内置占位皮肤 `skins/block/`。

## 9. 给装载器实现者的备忘

契约里每条规则都对应一个可单测的纯函数，按[架构大纲 P2](../../架构大纲.md) 的接口拆：

| 契约条款 | 实现落点 |
|---|---|
| 第 3 节字段规则 | `validateManifest(raw) → {ok:true, manifest} \| {ok:false, errors[]}`，纯函数，输入是 `unknown`（JSON 解析结果），所以类型收窄要自己做 |
| 第 6 节的 `core_gaps` | `missingRequiredPools(manifest) → string[]` |
| 第 4.2 节的地址规则 | `clipPath(skin, pool, name) → string`，只按名字拼，禁止下标 |
| 第 5 节体检 | **不进装载器**。留在 `tools/alpha-report.mjs`，作为交付前闸门；生产代码不许依赖 `ffmpeg-static` |
| 素材文件是否真存在 | `loadSkin(dir)` 里做，需要 `node:fs`，所以它在 `src/main/`，不在 `src/shared/` |

注意第 5 条：`src/shared/**` 不许 import `node:fs`（分层铁律），所以"读目录"留在主进程，"校验结构"留在 shared，两层各自可测。

**本次定契约时改了计划里的类型定义**（Task 5 落地按新形状写）：`SkinManifest` 补了 `author?` 与 `weights?`；`AnimationMeta` 的三个字段从必填改为可选，由校验按 3.1 的池名规则补默认值——否则作者每条动画都要重复写 `loop` 和 `mirrorable`。
