# with-me 桌宠 · 架构大纲

> 定位：这是 `docs/桌宠-Windows实现方案.html`（设计与取舍的理由）和 `docs/superpowers/plans/2026-11-02-desktop-pet-v1.md`（逐步施工单）之间的**结构总纲**。
> 大纲回答「系统由哪几块组成、每块用什么技术实现、块与块之间靠什么说话」，不重复论证为什么这样选。
> 阅读顺序：[设计 HTML](桌宠-Windows实现方案.html)（为什么这样选）→ [功能规格](superpowers/specs/2026-11-02-desktop-pet-v1.md)（交付什么、怎么算验收、哪些约束不可协商）→ 本文件（由哪几块组成）→ [皮肤包契约](superpowers/specs/2026-11-02-skin-pack-contract.md)（换角色等于换一个目录）→ [计划](superpowers/plans/2026-11-02-desktop-pet-v1.md)（怎么一步步做）。
> 本文件是**描述性**的：规格与契约才是约束性的，两边不一致时以那两份为准。

## 1. 目标与非目标

**v1 目标**：Windows 桌面上站着一只可换皮肤的宠物，按规则和权重随机播动画，鼠标悬停 400 毫秒出现按钮面板，点按钮切动作，其余区域鼠标完全穿透到下面的窗口。

**v1 明确不做**：多宠物、养成数值衰减与离线补算、小游戏、agent 接入、换装、macOS 实现（只留接口形状）、安装包与自动更新。

## 2. 分层与依赖方向

三块，依赖只能从上往下，反向依赖一律视为架构违规。

```
        ┌──────────────────────────────────────────┐
        │ 主进程 src/main        能碰操作系统      │
        │ 建窗 · 协议 · 光标轮询 · 穿透租约执行 · │
        │ 皮肤装载 · 存档 · 全屏让路              │
        └───────────────┬──────────────────────────┘
                        │ IPC 消息表（shared/ipc.ts 唯一来源）
        ┌───────────────▼──────────────────────────┐
        │ 渲染层 src/renderer    画宠物 + 全部规则  │
        │ 播放器 · 行为调度 · 命中判定 · 悬停 · 面板│
        └───────────────┬──────────────────────────┘
                        │ 只读数据
        ┌───────────────▼──────────────────────────┐
        │ 皮肤包 skins/          manifest + webm    │
        └──────────────────────────────────────────┘

        shared/ 是三层共用的纯逻辑与类型：不 import electron、不 import node:fs、不碰 DOM
```

三条依赖铁律（每条都有对应的检查命令，写在计划里）：

1. `src/shared/**` 不许 import `electron`、`node:fs`、`node:path` 之外的运行时模块，不许引用 `window`/`document`。这样它才能在三层里复用，并且全部能被 vitest 直接测。
2. `src/renderer/**` 不许 import `src/main/**`。渲染层拿皮肤靠消息，不靠自己读盘。
3. `src/main/**` 里除了 `platform.ts` 及其实现，任何文件不许直接调用 Electron 的窗口方法。业务代码要动窗口，只能走那四个动作。

## 3. 六个部分

### P1 平台层（`src/main/platform.ts` + `windows.ts` + `protocol.ts` + `cursor.ts` + `clickthrough.ts`）

| 项 | 内容 |
|---|---|
| 职责 | 把「操作系统窗口」这件事包成四个动作：建窗、接住/放开鼠标、推进光标、能否聚焦。隐藏 Windows 与将来 macOS 的差异 |
| 技术 | Electron 的 `BrowserWindow`；透明整屏覆盖窗（尺寸 = 主屏工作区，永不移动、永不改大小）；`setIgnoreMouseEvents`；`screen.getCursorScreenPoint()` 每 33ms 轮询 |
| 关键接口 | `interface Platform { createWindow(); setInteractive(on); sendCursor(p); setFocusable(on); onPageReady(cb); send(channel, payload); windowHandle(); show(); hide() }`。窗口方法只准出现在 `windows.ts` |
| 用 Java 类比 | 这是 `interface` + 一个 `WindowsImpl`。将来 macOS 就是再写一个 `MacImpl` 装配进来，业务代码一行不改 |
| 风险 | ~~整屏透明窗 + 保留硬件加速未实测~~ 已实测通过（2026-11-02 spike）。剩下的风险：穿透开着时网页收不到 `mousemove`，判定只能靠推进来的光标，所以轮询一断宠物就"瞎"；以及 `setIgnoreMouseEvents` 在遇到高完整性级别的前台窗口时可能失效（UIPI），因此租约超时兜底不能省 |

### P2 皮肤包（`skins/<id>/` + `src/main/skin-store.ts` + `src/shared/skin.ts`）

| 项 | 内容 |
|---|---|
| 职责 | 让「角色」变成纯数据。程序不认角色名，只认包 |
| 技术 | 一个目录 + `manifest.json` + `animation/<池>/<名字>.webm`。装载时先校验 JSON 结构，再检查素材文件是否真存在，最后检查必需池齐全 |
| 关键接口 | `validateManifest(raw)` → 通过给出 `SkinManifest`，不通过给出**逐条错误文字**；`loadSkin(dir)` → `LoadedSkin`；`missingRequiredPools(manifest)` |
| 三条硬规矩 | 动画按**名字**寻址（禁止数组下标）；动画名不许含 `/\:*?"<>|`（要拼路径）；必需池缺失就拒绝装载并说清缺哪条，不静默回退默认皮肤 |
| 风险 | 用户自制皮肤质量参差，所以素材体检（透明通道残留检查）必须在装载里，否则「我的宠物有块灰底」这类问题会变成你的日常工单。契约的权威版本在[皮肤包契约 spec](superpowers/specs/2026-11-02-skin-pack-contract.md) |

### P3 播放器（`src/renderer/player/`）

| 项 | 内容 |
|---|---|
| 职责 | 「播一段动画」这件事的抽象。业务只说「播 `idle/patrol`」，不知道底下是什么 |
| 技术 | 两个 `<video>` 元素轮流当前台 + CSS 透明度交叉淡入。素材通过自定义协议 `app://` 提供 |
| 关键接口 | `ClipPlayer { prepare(ref); play(ref) → Promise<'ended'\|'cancelled'>; cancel(); current; generation; destroy() }`。**没有 loop 概念**：spike 实测 `<video loop>` 每次回起点都重新缓冲，重复播放由行为层再调一次 `play()` 完成 |
| 曾计划但 v1 不做的能力 | `frameIndex()` / `snapshot()` / `hitTest()` 已删除——v1 没有调用方（命中判定走 `geometry.anyContains`），按编码规则 16 不预留空接口。v3 做逐像素点击或帧对齐时再加，届时是有意改动而不是顺手带上 |
| 换后端的钩子 | 第二、三轮如果需要逐像素点击或任意帧切入，加一个 `FrameBackend`（图片序列 + Canvas 逐帧画），`ClipPlayer` 的接口和调用方都不动 |
| 四条铁律 | ① 等新素材 `loadeddata` 之后再切换 ② 每次 play 递增代际号，过期回调丢弃 ③ 退位的 video 要摘掉 `onended` ④ 用 0.18s 透明度过渡垫接缝 |

### P4 行为调度（`src/shared/rules.ts` + `behavior.ts`，执行在渲染层）

| 项 | 内容 |
|---|---|
| 职责 | 决定「接下来播哪一条」 |
| 技术 | 两层。规则层是纯确定性逻辑：被点→回应、拖拽→被拖、刚互动完那一拍→归位待机、久无人理→**交出选池决策权**；随机层按 manifest 的池权重在 idle/move/turn 里抽，并排除刚播过那条 |
| 关键接口 | `createRuleEngine(now, idleLongMs).feed(event) → poolName \| AMBIENT_POOL`；`createPicker(rng).pickFrom(skin, pool, current)` / `.pickAmbient(skin, current)`；接缝 `nextClip({rules, picker, source, loops, ref}) → {kind:'loop'\|'play', ref}` |
| 为什么规则层不直接说「走动」 | 早先它超时后每拍都返回 `move`：那样皮肤的 `weights` 永远用不上、`turn` 永远不会自主出现，而且宠物会一路走到撞墙回头再继续走。选池本来就是随机层的活 |
| 可测性 | 时钟和随机源都是**注入**进来的。等价于 Java 单测里传 `Random(seed)` 和 `FakeClock`，同一条测试跑十次结果一致 |
| 硬规矩 | 权重与池定义全部来自皮肤 manifest，代码里不写一个数字 |

### P5 交互层（`src/shared/hover.ts` + `geometry.ts` + `src/renderer/panel.ts` + `sprite.ts`）

| 项 | 内容 |
|---|---|
| 职责 | 屏幕上同时存在三种区域：身体（可点可拖）、面板（按钮可点）、其余（穿透）。这一层负责算出前两块，并据此申请/放开鼠标 |
| 技术 | 纯函数几何换算（画布 640×360 坐标 → 覆盖层 CSS 坐标）；悬停计时器（停留满 400ms 开、离开满 400ms 关）；穿透租约（渲染层每帧续期，主进程 500ms 超时兜底，卡死也不会让整块屏幕点不动） |
| 关键接口 | `bodyRect(manifest, petPos, override?)`、`anyContains(rects, p)`、`createHoverTimer(now).onPoint(p, overBody, overPanel) → 'open'\|'close'\|'none'`、`.pendingMs(now) → 剩余毫秒 \| null`、`createPanel(root, actions, onClick).rect()` |
| 静止的光标 | 主进程只对**变化过**的坐标发消息（相同坐标去重），所以手真的停在宠物上不动时不会有第二次 `onPoint` 进来。开合得由渲染层按 `pendingMs` 自己挂定时器催——不然「悬停 400ms 弹面板」实际变成了「再动一下鼠标才弹」 |
| 硬规矩 | 每条动画可以覆盖身体框（趴下、躲藏这类轮廓剧变的动作必须覆盖）；面板显隐只能靠 `opacity` + `hidden`，改成 `display:none` 会让控件矩形量到 0 |
| 风险 | 面板矩形内的点击全部被桌宠吞掉，所以面板必须有明确关闭途径，否则用户会觉得鼠标被偷了 |

### P6 持久化（`src/shared/save.ts` + `src/main/storage.ts` + `paths.ts`）

| 项 | 内容 |
|---|---|
| 职责 | 存「用哪个皮肤、数值、上次时间」，并且坏了不能崩 |
| 技术 | 一个 `save.json` 放在 `app.getPath('userData')`；先写临时文件再 `rename`（原子写，不会留下半个文件）；覆盖前把上一版复制成 `.bak`；读的时候主档坏就读备份，都坏就回默认值并记一条 warning，永不抛异常 |
| 关键接口 | `migrate(raw) → SaveData`、`saveTo(dir, data)`、`loadFrom(dir)`、`platformDataDir()`、`applyCare(save, action, delta)`（数值写入的**唯一入口**） |
| v1 的取舍 | `stats` 四个字段先存在、值固定、不参与判断；`applyCare` 这个入口先建好。衰减公式和离线补算**不提前写**——第一版没有调用方，写了没人验证，到第二轮还得重测 |

## 4. 模块格式与资源加载（这次定的，不能再摇摆）

| 决定 | 内容 | 为什么 |
|---|---|---|
| 代码格式 | Node ESM，`package.json` 里 `"type": "module"`；所有相对 import **必须写 `.js` 后缀** | Node 的 ESM 不认无后缀相对路径；TypeScript 用 `module/moduleResolution: NodeNext` 时按写什么发什么 |
| 页面加载 | 注册自定义协议 `app://`，资源根按**主机名**区分：`app://assets/...` 指向 `dist/`，`app://skin/...` 指向皮肤的 `animation/` 目录；窗口加载 `app://assets/renderer/index.html` | **Chromium 禁止 `file://` 页面 import ES 模块，也把 `file://` 的视频当跨源素材**。两个参考项目都栽在这里：qqpet 用 `app://`，dsh-pet 用 `dsh-pet-bridge:`。不能用 `app:///renderer/...` 这种路径首段当根名——standard 协议下 Chromium 会把首段搬进主机位，处理器按首段找根永远 403（spike 实测） |
| 皮肤素材 | 走同一个 `app://` 协议，路径映射到绝对皮肤目录 | 与页面同源，CSP 不用开后门；协议层顺便做路径穿越防护（`..` 一律拒绝） |
| 预加载脚本 | `src/preload/index.cjs`，**单个文件、零 import**，消息名字符串就地内联 | `contextBridge` + preload 的沙箱限制。用一条测试锁定内联字符串与 `shared/ipc.ts` 一致，防止两边跑偏 |
| 打包器 | 不用。构建 = `tsc` + 一个复制 html/css 的小脚本 | 少一个依赖少一类坑。第一版没有需要打包的东西 |
| 硬件加速 | 保持开启，禁止调用 `app.disableHardwareAcceleration()` | dsh-pet 关掉它换来的是视频全靠 CPU 解。这是本项目要避开的那个决定 |

## 5. 三份契约

契约变更要写迁移逻辑，不能原地改字段含义。

**5.1 IPC 消息表**（`src/shared/ipc.ts`，唯一来源，前缀统一 `pet:`）

| 通道 | 方向 | payload |
|---|---|---|
| `pet:cursor` | main → renderer | `{x, y}` 覆盖层内坐标 |
| `pet:skin-loaded` | main → renderer | `LoadedSkin` 或 `{errors: string[]}` |
| `pet:click-through` | renderer → main | `{grab: boolean}` |
| `pet:focusable` | renderer → main | `boolean` |

只有这两条 renderer → main 通道有真实行为。命中区可视化由渲染层本地切换，点名下条动画由渲染层直接调播放器——都不需要过 IPC，所以对应通道没有加：留一条没人发的通道，比少一条通道更糟。

**5.2 皮肤 manifest**（`formatVersion` 当前 = 1）

字段的完整规则、命名约束、素材规格与校验拒绝清单见[皮肤包契约 spec](superpowers/specs/2026-11-02-skin-pack-contract.md)，那里是权威版本。下面这份只到能看懂结构的程度：

```jsonc
{
  "formatVersion": 1,
  "name": "色块",
  "canvas": { "w": 640, "h": 360, "feetY": 330 },
  "bodyBox": { "x": 200, "y": 50, "w": 240, "h": 285 },
  "pools": { "idle": ["patrol", "patrol2"], "turn": ["left"], "move": ["step"],
             "click": ["tapped"], "drag": ["pulled"] },
  "weights": { "idle": 5, "move": 3, "turn": 1, "click": 1, "drag": 1 },
  "animationMeta": { "patrol": { "mirrorable": true } },
  "hotspots": {}
}
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `formatVersion` | 是 | 程序只认支持范围，不认就报错停下，不猜 |
| `canvas` | 是 | 素材尺子，锁 640×360 |
| `bodyBox` | 是 | 身体占的画布矩形，贴边与命中的依据。**动画任何一帧的可见像素都不许出这个框**——角色跑出框会导致鼠标停在看得见的身上不弹面板。位移交给程序移动舞台，不写在动画里；轮廓剧变的动作要在 `animationMeta` 里单独给框（spike 前用占位皮肤实测踩到） |
| `pools` | 是 | 池名 → 动画名数组。必需池：`idle/turn/move/click/drag` |
| `animationMeta` | 否 | 每条动画的循环性、可否镜像、身体框覆盖。缺省按**池名**定：`idle/turn/move` 循环，`click/drag` 与自定义池一次性（与皮肤契约 spec 一致，早期写的「按池内条数」已废弃） |
| `weights` | 否 | 池名 → 正数，只用于久无人理后自主选池；同池内多条动画均匀随机。缺省全 1 |
| `hotspots` | 否 | v2 互动用，v1 只透传不解释 |

**5.3 存档 schema**（`SAVE_VERSION = 1`）

```jsonc
{ "version": 1, "skin": "block", "stats": { "hunger": 80, "mind": 80, "clean": 80, "mood": 80 },
  "lastSeenAt": 1762000000000 }
```

## 6. 素材管线（七步，术语随手注释）

```
三视图 → 写提示词 → 蓝幕生成视频 → 去水印 → 抠像 → 归一化 → 编码 webm → 体检
```

| 步 | 做什么 | 术语与坑 |
|---|---|---|
| 生成 | 16:9、10 秒、蓝幕 `#0000FF` | 不用绿幕：角色有荧光绿发光件，绿幕会把它一起抠掉 |
| 抠像 | 识别背景色 → 写进 **alpha 通道**（每个像素的透明度） | 接近全透明的像素要直接写 0；透明区的 RGB 要抹平，否则背景色会渗进边缘 |
| 归一化 | 统一身高、居中，脚底对齐 `feetY` | 缩放会二次损害边缘，一次到位 |
| 编码 | VP9 + alpha 的 WebM，`-c:v libvpx-vp9`、`-crf 8`、`-b:v 0`、`-auto-alt-ref 0` | 不显式写 libvpx-vp9 会**静默丢 alpha**；走 `yuva420p` 之外的路径会把 alpha 做色度二次采样（降分辨率存储 → 边缘发虚） |
| 体检 | 抽帧统计背景区 alpha 分布 | dsh-pet 的脚本只查「alpha 有没有丢」，不查残留浓度，这一项要自己补 |

**唯一合同**：**动画周期要整除素材时长**，每段从标准正面姿势起步并回到该姿势。因为播放器只能从头播（视频按关键帧压缩，没法从任意帧干净切入），所以交接处的姿势连续性全靠这条——末帧回不到首帧，每次换动画都会看见一跳。详见皮肤契约 spec 第 4.1 节。

## 8. 编码规则（评审时按这几条挑刺）

1. 时间、尺寸、池名等所有数字与常量只在 `src/shared/config.ts` 出现一次。
2. 纯逻辑优先：判定、计时、抽取、换算写成不依赖 Electron/DOM 的函数，能传 `now`、`rng` 就传进去。
3. 动画只按名字取。出现 `pools[i]` 这类下标寻址即打回。
4. 渲染层不 import 主进程模块；shared 不 import electron / node:fs。
5. 窗口操作只走 `Platform` 的四个动作。
6. 出错要大声：皮肤不合法就显示错误列表，存档坏了就在 `warnings` 里留痕，不许静默兜底成「看起来正常」。
7. 每个任务先写失败测试再实现，测试跑不过不许提交。
8. 不写没有调用方的代码。预留靠接口和字段，不靠空函数。

## 9. 分期

## 10. 还没闭合的风险

1. **蓝幕抠像脚本要自研**：两个参考项目的脚本都是绿幕专用，色相区间和阈值得重写。占位皮肤走通了 `colorkey` 最简管线，但那是色块，换成真实角色素材时的容差与溢色处理还没验。
2. **角色形象授权未定**：大肥鱼形象原作者以「署名 · 非商业 · 相同方式共享」开放二创但禁商用；「缓存」有完整设定但三视图要重做。v1 用色块皮肤，所以这件事可以推到出真实动画之前。
3. **内存基线不干净**：spike 那轮把截图缓冲区算进了 Browser 进程，需要一次不带测量的干净读数（规格第 8 节的预算因此留了余量）。

**已闭合**：整屏透明窗 + 保留硬件加速在真机成立（2026-11-02 spike，见 `spike/README.md`）。退路「固定尺寸单窗 + 搬 dsh-pet 的三态判定函数」不需要启用，内容仍留在 spike README 里备查。
